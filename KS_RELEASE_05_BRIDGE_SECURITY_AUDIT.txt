------------------------------------------------------------------------------------------------
1. Exact Location & Diff (`apps_script/WebAppBridge.js`, `ksExpandSciNumber_` & `ksNormalizeReadbackVal_` lines 660–703):
   BEFORE (`c8e5a15`, prior lines 628–652):
     - `ksNormalizeReadbackVal_` tested `KS_PLAIN_DECIMAL_RE.test(numStr)` on JS `typeof val === 'number'`,
       so tiny finite JS floats like `0.0000005` (`String(val) === "5e-7"`) skipped `ksFormatPlainDecimal_`
       and returned `"5e-7"`, disagreeing with Python `_normalize_scalar` (`"0.0000005"`).
   AFTER (`e4e86802` / current lines 660–703):
     - Added pure helper `ksExpandSciNumber_(numStr)` (lines 660–676) that expands exact decimal digits
       of `^([+-]?)(\d+)(?:\.(\d+))?[eE]([+-]?\d+)$` without float arithmetic and routes the result
       through `ksFormatPlainDecimal_`.
     - Invoked STRICTLY inside the `if (typeof val === 'number') { if (isFinite(val)) { ... } }`
       branch (lines 688–690) — NEVER on string inputs.
2. Why the Change Was Required:
   Google Sheets stores numeric cells as IEEE-754 numbers and returns JS `typeof val === 'number'`
   on `getValues()`. For values `< 1e-6` (e.g., trace spice quantities or small decimal rates like
   `0.0000005`), JS `String(val)` outputs `"5e-7"` while Python `Decimal` outputs `"0.0000005"`,
   triggering false `READBACK_VERIFICATION_FAILED` quarantine faults.
3. Threat Class Mitigated:
   Read-back verification false-positive denial-of-service on valid decimal writes AND prevention
   of silent string-to-number coercion attacks on SKU/lot identifiers (like `"1E2"` or `"0010"`).
4. Security Boundary & Preconditions Enforced:
   Called inside `ksWriteCanonicalRowByHeaders_` (lines 1183–1184) AFTER `SpreadsheetApp.flush()`
   (line 1158) and fresh `sh.getRange(targetRow, 1, 1, lastCol).getValues()[0]` read-back (line 1159),
   verifying EVERY written column in `flatData`.
5. Exact Failure Behavior (Fail-Closed Guarantee):
   - Any mismatch between normalized `expectedRow[idx]` and normalized `readBack[idx]` throws
     `READBACK_VERIFICATION_FAILED` (lines 1185–1190), caught by `doPost` with
     `businessWriteAttempted = true` -> logs `ExceptionRegister` -> returns `status: 'RECOVERY_REQUIRED'`,
     `http_status: 409`, `retryable: false` (lines 1005–1049).
   - Non-finite JS values (`NaN`, `Infinity`, `-Infinity`) bypass expansion (line 683 `isFinite(val)`).
   - String codes like `"0010"`, `"1E2"`, `"12.34.56"`, `"12abc"`, `""`, `null` are NEVER coerced
     to numbers (Note: `KS_PLAIN_DECIMAL_RE` at line 639 rejects leading-zero multi-digit integers
     such as `"0010"` because integer part requires `0|[1-9]\d*`).
6. Lock & Side-Effect Safety:
   Pure deterministic string transformation; zero external calls, zero mutations, bounded linear
   work relative to digit length.
7. Compatibility with Python Backend:
   Exact 27-vector parity verified against `backend/app/apps_script_bridge.py::_normalize_scalar`
   (lines 213–245) and `_format_decimal_canonical` (lines 196–210).
8. Integer & Negative-Zero Preservation:
   `10` -> `"10"`, `100` -> `"100"`, `100.00` -> `"100"`, `-0.00` -> `"0"`, `""` -> `""`, `null` -> `""`,
   `true` -> `"true"`, `false` -> `"false"` (`10 != 100`, `"" != "0"`, `false != "0"`).
