0. NEW SECURITY HARDENINGS DISCOVERED & CLOSED DURING KS-RELEASE-04 AUDIT
------------------------------------------------------------------------------------------------
During Stage D, E, and F adversarial testing against `apps_script/WebAppBridge.js`, three subtle
fail-closed edge cases were uncovered and fixed immediately (synced byte-identically to both
`apps_script/WebAppBridge.js` and `apps_script_patch/first_owner_bootstrap/merged_bound_files/WebAppBridge.js`,
SHA-256 `776bd3690842501f97d4967c19c62966a5da974e6f555686abdf145f4109eff6`):

  [H1 — Stage D] Incomplete AuditLog Replay Metadata Fail-Closed Quarantine:
    - Root cause: In `doPost` replay path, `if (auditMeta.payload_hash && ...)` only compared
      payload_hash when `hash=<64hex>` was present in `AuditLog.new_value`, allowing a corrupted or
      truncated `AuditLog` row missing `hash=<hex>`, `action`, or `actor_user_id` to pass replay.
    - Fix: Explicitly require non-empty `auditMeta.action`, `auditMeta.actor_user_id`, AND
      64-hex `auditMeta.payload_hash`; any omission fails closed to `status: 'RECOVERY_REQUIRED'`,
      `error_code: 'NONCE_AUDIT_METADATA_INCOMPLETE'`, `http_status: 409`, `retryable: false`.

  [H2 — Stage E] Duplicate User Identity & Malformed Row Fail-Closed in `ksVerifyBridgeActor_`:
    - Root cause: `ksVerifyBridgeActor_` previously returned on the first matching `user_id` row
      without checking for duplicate rows or truncated/malformed row arrays.
    - Fix: Scan ALL data rows in `Users`, fail closed on short/non-array rows
      (`ACTOR_DIRECTORY_MALFORMED_ROW`, HTTP 503), collect all case-insensitive trimmed `user_id`
      matches, and reject duplicates (`ACTOR_DUPLICATE_IDENTITY`, HTTP 403) matching Python's
      `AMBIGUOUS_IDENTITY` guard.

  [H3 — Stage F] Scientific-Notation JS Number Read-Back Normalization Parity:
    - Root cause: JavaScript `String(0.0000005)` formats as `"5e-7"`, whereas Python's `Decimal`
      formats `"0.0000005"` (`format(dec, "f")`), causing false read-back mismatches for tiny
      decimal quantities/rates.
    - Fix: Added `ksExpandSciNumber_(num)` inside `ksNormalizeReadbackVal_` strictly for finite JS
      `typeof val === 'number'` values whose string contains `e`/`E`, expanding exact decimal
      digits while preserving string literals (`"1E2"`, `"0010"`) completely uncoerced.

STAGE D: D-1 PAYLOAD HASH, CANONICAL HMAC BINDING & 7 FAILURE-POINT VERIFICATION
================================================================================================

ARCHITECTURAL CLARIFICATION ON CHECK #3 (PYTHON <-> APPS SCRIPT HASH & HMAC BINDING):
  - Python (`backend/app/transaction_safety.py::compute_deterministic_payload_hash`) computes
    the deterministic canonical SHA-256 `payload_hash` and embeds it inside `canonical_envelope`.
  - Python (`AppsScriptBridge.sign_envelope`) then computes HMAC-SHA256 over the exact UTF-8
    bytes of `canonical_envelope` (`sort_keys=True, separators=(',',':'), ensure_ascii=True`).
  - Apps Script (`WebAppBridge_BootstrapIntegration.js::ksVerifySignedBridgeEnvelope_`) independently
    recomputes HMAC-SHA256 over `canonical_envelope` (verified byte-identical to Python for ASCII
    and Unicode in `test_cross_language_hmac.py` #01 & #02), verifies constant-time equality,
    verifies outer wire fields match signed fields (binding actor, target_tab, action, nonce,
    payload_hash, timestamp), validates `payload_hash` is mandatory valid hex (`^[0-9a-f]{16,128}$`),
    and persists/enforces `hash=<payload_hash>` in `AuditLog` on replay (failing closed to
    RECOVERY_REQUIRED if missing or incomplete). Apps Script relies on the HMAC-authenticated
    `payload_hash` from `canonical_envelope` rather than re-hashing `req.payload` independently.
