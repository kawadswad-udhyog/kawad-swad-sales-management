3. CRITICAL WEB-APP BRIDGE FINDINGS
File WebAppBridge.js; doPost is the HTTP entry point found in this archive.
3.1 HMAC is optional in current source. doPost requires SALES_APPS_SCRIPT_SHARED_SECRET to exist and be at least 32 characters. It extracts signature from query or body, but compares HMAC only inside `if (providedSig)`. If signature is absent, the HMAC check is skipped and execution proceeds. This is a source-observed authentication defect. Live exploitability and deployed-source identity are unverified.
3.2 Caller-controlled actor fields. actor_user_id and actor_role are read directly from request body. The bridge passes actorUserId/actorRole to routing, but the shown dispatcher does not authenticate the claimed identity against a trusted user/session record. The generic fallback stores caller-supplied created_by. This is a source-level trust-boundary defect unless an external authenticated envelope is enforced elsewhere; no such verification is visible in doPost.
3.3 Generic fallback writer. ksWriteCanonicalRowByHeaders_ calls getSheetByName(targetTab), maps caller payload keys to headers, then setValues or appendRow. No target-table allowlist or per-table field allowlist is visible in this function. This is a broad arbitrary-sheet write surface if bridge dispatch can reach the fallback.
3.4 Dispatch fallback behavior. ksRouteGovernedWrite_ has ten named action branches (raw material receipt, production order, material consumption, production output, quality decision, packaging batch, sales order, sales invoice, customer payment, journal voucher). All other actions fall through to the generic writer. There is no closed default rejection for unknown action names in the shown code.
3.5 Replay/idempotency defect. ksFindByNonce_ searches IdAllocations by nonce only and returns allocated_id/tab_name. It does not compare action, target table, payload hash, actor, or transaction fingerprint. A matching nonce returns CONFIRMED before route execution. Bridge allocation recording is separate from IdAllocator.js. A duplicate nonce across unrelated actions/tables can therefore be misclassified as a successful replay, subject to actual sheet contents and callers.
3.6 Allocation record write. ksRecordIdAllocation_ directly appends to IdAllocations and does not call central allocator/SafeWriter. It may silently return when sheet missing or headers absent, yet doPost still returns CONFIRMED after calling it.
3.7 Error response. doPost catches all errors and returns REJECTED, but does not expose a stable transaction status/readback protocol in this file. No independent live call was attempted.

4. AUTHENTICATION AND ROLE MODEL
AuthAndMenu.js defines ksGetCurrentUserContext_ and ksRequireRole_. Context resolves active user by email against Users, with owner fallback. Role guard checks authenticated and allowedRoles. These are positive controls for callers that actually invoke them.
onOpen builds role-filtered menus. Menu visibility is a user-interface convenience, not a security boundary. Global server functions may still be invoked by authorized script editors or other server-side callers.
ksUiSubmitExpenseVoucher explicitly calls ksRequireRole_ for OWNER_ADMIN, PA, ACCOUNTS and validates nonce, amount and accounts.
ksUiSubmitSalesEntry does not itself call ksRequireRole_; it directly calls ksCreateSalesOrder and optionally ksCreateSalesInvoice. The callee bodies must enforce roles on every route. No assumption of upstream protection is accepted without call-chain proof.
Bridge actor_role is request-controlled in doPost and is not equivalent to ksGetCurrentUserContext_. Role checks in UI context do not authenticate web-app bridge callers.
