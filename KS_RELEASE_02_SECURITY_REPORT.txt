1. STAGE 5 — APPS SCRIPT BRIDGE DEEP SECURITY REMEDIATION (W1 - W6)
--------------------------------------------------------------------------------
All 6 bridge security controls (W1 through W6) were implemented in the actual bound
Apps Script files (`apps_script/WebAppBridge.js` and `apps_script/AuditAndExceptions.js`),
synchronized to `apps_script_patch/first_owner_bootstrap/merged_bound_files/`, and
verified end-to-end via Node VM execution of the actual files in
`backend/tests/test_cross_language_hmac.py` (tests 01-20) and
`backend/tests/test_apps_script_bootstrap_vm.mjs` (suites 1-7).

  [W1] Mandatory Strict Locked Audit + Attributable Post-Write Quarantine
  - Status   : PASSED (Unit & VM Verified; REQUIRES GPT INDEPENDENT REVIEW)
  - Evidence :
      * apps_script/AuditAndExceptions.js:180 (`ksLogAuditStrictLocked_`) — never
        acquires or releases ScriptLock; allocates AUD-* ID via `ksAllocateIdLocked_`.
      * apps_script/AuditAndExceptions.js:252 (`ksLogExceptionLocked_`, NEW in R02) —
        writes forensic exception record to `ExceptionRegister` WITHOUT acquiring or
        releasing caller's `ScriptLock`, ensuring uninterrupted lock ownership even
        during quarantine error paths.
      * apps_script/WebAppBridge.js:640 (`doPost`) — verifies `ksLogAuditStrictLocked_`
        exists BEFORE lock acquisition/write (HTTP 503 `MANDATORY_AUDIT_LOGGER_MISSING`);
        removed any silent fallback to legacy `ksLogAudit_`. Any failure after business
        mutation calls `ksLogExceptionLocked_` and returns HTTP 409 `RECOVERY_REQUIRED`
        (`retryable: false`, `error_code: BRIDGE_POST_WRITE_FAILURE`, with
        `recovery_exception_id`).
  - Tests    : test_10, test_11, test_14, test_18 (PASSED).

  [W2] Replay & Nonce Collision Protection (Tab + Action + Actor + Payload Hash)
  - Status   : PASSED (Unit & VM Verified; REQUIRES GPT INDEPENDENT REVIEW)
  - Evidence :
      * apps_script/WebAppBridge.js:609 (`ksFindAuditReplayMetadata_`) and `doPost`:
        every governed write records `related_record_id = nonce` and embeds
        `hash=<payload_hash>` in `AuditLog.new_value`.
      * On nonce replay, compares persisted `IdAllocations` + `AuditLog` metadata against
        incoming request across ALL four dimensions:
          1. Target tab mismatch  -> HTTP 409 `NONCE_TARGET_TAB_CONFLICT`
          2. Action mismatch      -> HTTP 409 `NONCE_ACTION_CONFLICT`
          3. Actor mismatch       -> HTTP 409 `NONCE_ACTOR_CONFLICT`
          4. Payload hash mismatch-> HTTP 409 `NONCE_PAYLOAD_HASH_CONFLICT`
      * Only exact 4-way matches return idempotent `CONFIRMED` (`idempotent_replay: true`).
  - Tests    : test_10, test_12, test_17 (PASSED).

  [W3] Strict 133-Action-to-Tab Allowlist + Control-Table Hard Block + Role Gates
  - Status   : PASSED (Unit & VM Verified; REQUIRES GPT INDEPENDENT REVIEW)
  - Evidence :
      * apps_script/WebAppBridge.js:17 (`KS_BRIDGE_PROTECTED_GOVERNANCE_TABS`:
        `AuditLog`, `IdAllocations`, `ExceptionRegister`) -> HTTP 403

  [W4] Authoritative Server-Side Actor Directory Verification (Inside ScriptLock)
  - Status   : PASSED (Unit & VM Verified; REQUIRES GPT INDEPENDENT REVIEW)
  - Evidence :
      * apps_script/WebAppBridge.js:342 (`ksCanonicalizeBridgeRole_`) & line 493
